# EscApp-Games

Per-game modules for EscApp: launch settings, bottle contents and small edits to a game's settings files, as data.
The design is in `../EscApp/docs/GAME-MODULES.md`; read it before changing the format. The user speaks Russian:
answer in Russian, but files, comments and commit messages are English.

## Commands

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # jsonschema, pinned
.venv/bin/python -m unittest discover -s tests -t .                  # schema tests
```

Tools are Python (3.11+) so they run on Linux CI. The schemas check a module's shape only; what is allowed beyond
it (registry branches, file types, component names, unique match keys) belongs in `tools/check`.

## Rules

- Data only. Nothing here may be executable or a script a game or the system would run, and nothing may crack,
  bypass DRM or anti-cheat, or cheat (see `README.md`). Code fixes go into `../EscApp-Runtime`.
- `games.json` is generated by CI from `modules/` and `shared/`; never edit it by hand.
- Every file in `files/` has a `credits` entry in its module with an SPDX license that allows redistribution.
- A module's `note` says why each setting is there, naming the failure it fixes (as EscApp's doc comments do).
- A setting goes in only after it was checked on a real game in EscApp, on the Wine version the module names.
- Each change to a module bumps its `revision`.
- Never copy values or files from other projects' game databases; check on a real game and write our own.
